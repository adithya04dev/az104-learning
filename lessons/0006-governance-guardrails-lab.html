Azure governance · Guided lab

Govern a product sandbox without breaking production.

Apply tags, test a deny Policy, prove a deletion lock, inspect hierarchy, and configure a budget. The lab has permission tiers so a restricted tenant still produces useful evidence.

35–50 minutesPortal + Azure CLITiered permissions
Use only an approved sandbox.
A Policy assignment can block deployments. A lock can block cleanup. Scope every change to the dedicated lab resource group, record each created object, and remove Policy assignments before locks and locks before deleting the resource group. If you cannot verify the scope, stop and use observation mode.

Choose your path

Level A · Contributor
Create/tag a resource group and test a lock if authorized.
Level B · Policy authority
Add a narrowly scoped deny Policy and prove enforcement.
Level C · Read-only
Inspect inherited Policy, locks, hierarchy, tags, and budgets without changes.

Run the lab

1

Verify context and create the governed scope

az account show --query '{subscription:name, id:id, tenantId:tenantId}' -o table

AZ104_GOV_RG="rg-az104-governance-lab"
AZ104_GOV_LOCATION="eastus"

az group create \
  --name "$AZ104_GOV_RG" \
  --location "$AZ104_GOV_LOCATION" \
  --tags Product=Pulse Environment=Lab CostCenter=Learning

AZ104_GOV_RG_ID=$(az group show \
  --name "$AZ104_GOV_RG" \
  --query id -o tsv)

Predict: Will a child resource automatically inherit all three tags? Record “yes” or “no” and the reason.

Level C: Inspect an approved existing resource group and one child resource. Compare tags without editing either.
2

Prove that tags do not inherit automatically

Create a no-hourly-charge VNet without tags and compare it with the resource group.

az network vnet create \
  --resource-group "$AZ104_GOV_RG" \
  --name "vnet-az104-governance-lab" \
  --address-prefixes 10.105.0.0/16 \
  --subnet-name "snet-app" \
  --subnet-prefixes 10.105.1.0/24

az network vnet show \
  --resource-group "$AZ104_GOV_RG" \
  --name "vnet-az104-governance-lab" \
  --query tags

Evidence: A null or empty tag set confirms that the resource-group tags did not automatically copy to the VNet. Add tags explicitly or use Policy/automation.

3

Optional Level B: enforce a required tag with Policy

Resolve the built-in definition and assign it only to the lab resource group. Verify both IDs before creating the assignment.

AZ104_TAG_POLICY_ID=$(az policy definition list \
  --query "[?displayName=='Require a tag on resources'].id | [0]" \
  -o tsv)

printf '%s\n' "$AZ104_TAG_POLICY_ID"
printf '%s\n' "$AZ104_GOV_RG_ID"

az policy assignment create \
  --name "az104-require-environment-tag" \
  --display-name "AZ-104 lab - require Environment tag" \
  --policy "$AZ104_TAG_POLICY_ID" \
  --scope "$AZ104_GOV_RG_ID" \
  --params '{"tagName":{"value":"Environment"}}'

Predict: Will a new untagged VNet succeed? Will the existing VNet be deleted?

After allowing for assignment propagation, try an untagged VNet creation and record the denial. Then add --tags Environment=Lab and verify success. A Deny effect blocks a non-compliant request; it does not delete an existing resource.

az network vnet create \
  --resource-group "$AZ104_GOV_RG" \
  --name "vnet-az104-policy-test" \
  --address-prefixes 10.106.0.0/16

# Retry after observing the expected denial:
az network vnet create \
  --resource-group "$AZ104_GOV_RG" \
  --name "vnet-az104-policy-test" \
  --address-prefixes 10.106.0.0/16 \
  --tags Environment=Lab
Level C: On an approved scope, list Policy assignments and select one. Identify definition/initiative, assignment scope, exclusions, parameters, effect, and one compliance result. Do not assume non-compliance means remediation already occurred.
4

Remove Policy before testing the lock

az policy assignment delete \
  --name "az104-require-environment-tag" \
  --scope "$AZ104_GOV_RG_ID"

Verify: Confirm the assignment is absent at the lab scope. If you used observation mode, skip this command.

5

Prove CanNotDelete behavior

az lock create \
  --name "az104-protect-lab" \
  --lock-type CanNotDelete \
  --resource-group "$AZ104_GOV_RG"

# Expected to fail because the resource group is locked:
az group delete --name "$AZ104_GOV_RG" --yes

Predict: Can you still update the VNet? A CanNotDelete lock permits authorized modifications; ReadOnly would be more restrictive.

Evidence: Capture the error category showing the lock blocked deletion. The failure is the successful experiment.

Level C: Inspect locks at a resource and its parents. State whether each is direct or inherited and predict a control-plane delete, control-plane update, and data-plane operation.
6

Inspect management-group inheritance

In Management groups, locate the active subscription in the hierarchy. Do not create or move management groups. Trace upward to the root and identify one inherited Policy or RBAC assignment if visible.

Explain: Why would a company place Pulse production subscriptions beneath a product or geography management group instead of assigning the same Policy separately to every subscription?

7

Create or inspect a budget

At the lab resource-group scope, open Cost Management → Budgets. If authorized, create a temporary low-value monthly budget with an email threshold, then delete it after inspection. If Cost Management is not yet available, record the access or subscription-age blocker.

Predict: If spending crosses 100%, will Azure delete or stop the VNet? No. Budgets notify; they do not inherently stop consumption.

Verify: Identify the scope, reset period, actual/forecast threshold, recipients, and evaluation delay.

8

Unlock and clean up

az lock delete \
  --name "az104-protect-lab" \
  --resource-group "$AZ104_GOV_RG"

az group delete --name "$AZ104_GOV_RG" --yes

Final verification: Confirm the Policy assignment, lock, budget, and resource group you created are gone. Never delete similarly named objects without checking their full scope and creator.

Evidence gate

Explain one observed result for each tool: RBAC permission boundary, Policy enforcement/compliance, lock behavior, tag non-inheritance, management-group inheritance, and budget notification. Also name one thing each tool does not do.

Official procedures
  • Assign Azure Policy
  • Configure and understand locks
  • Manage tags with Azure CLI
  • Create and manage budgets

Ask your Codex teacher to review exact errors or unexpected results. Redact tenant IDs only if your organization treats them as sensitive; never share credentials or tokens.
