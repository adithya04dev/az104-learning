Azure RBAC · Guided lab

Prove scope inheritance with evidence.

Build a zero-compute-cost hierarchy, assign Reader to a group at the resource-group scope, and inspect the inherited assignment on a child VNet.

30–40 minutesPortal + Azure CLIResource group + VNet
Authorization and cleanup
Use an approved sandbox subscription. Creating role assignments requires Microsoft.Authorization/roleAssignments/write at the target scope, commonly through Role Based Access Control Administrator or another authorized role. A VNet itself has no hourly charge, but confirm your subscription policies. Create only the named lab resources and remove them at the end.

Scenario

The Pulse auditors group must view everything in one lab resource group. It must not change resources and must not see unrelated resource groups. You will prove that one group assignment at the resource-group scope reaches the child VNet.

Run the lab

1

Check context before creating

Open Cloud Shell or a local authenticated Azure CLI. Confirm the active tenant, subscription, and signed-in identity. Stop if the subscription is not your approved sandbox.

az account show --query '{subscription:name, subscriptionId:id, tenantId:tenantId, signedInAs:user.name}' -o table

Predict: At which scope do you need role-assignment write permission?

2

Create the lab hierarchy

Choose an allowed region. These commands create one resource group and one child VNet.

AZ104_RBAC_RG="rg-az104-rbac-lab"
AZ104_RBAC_LOCATION="eastus"

az group create \
  --name "$AZ104_RBAC_RG" \
  --location "$AZ104_RBAC_LOCATION" \
  --tags Purpose=AZ104 Environment=Lab

az network vnet create \
  --resource-group "$AZ104_RBAC_RG" \
  --name "vnet-az104-rbac-lab" \
  --address-prefixes 10.104.0.0/16 \
  --subnet-name "snet-app" \
  --subnet-prefixes 10.104.1.0/24

Verify: In the portal, draw the scope chain: subscription → resource group → VNet.

3

Choose the principal, role, and scope

Use the az104-pulse-engineers group from the previous lab or create an approved lab security group. Record its object ID. Do not rely on a potentially duplicated display name.

AZ104_RBAC_GROUP_ID="<group-object-id>"
AZ104_RBAC_RG_ID=$(az group show \
  --name "$AZ104_RBAC_RG" \
  --query id -o tsv)

az role assignment create \
  --assignee-object-id "$AZ104_RBAC_GROUP_ID" \
  --assignee-principal-type Group \
  --role Reader \
  --scope "$AZ104_RBAC_RG_ID"

Predict before running: Will this assignment be direct or inherited when viewed on the VNet?

Observation mode: If role assignment creation is blocked, open Access control (IAM) → Role assignments on an approved resource. Find one inherited assignment and identify its principal, role, assignment scope, and current viewing scope.
4

Inspect the child scope

Use the portal's VNet Access control (IAM) view and include inherited assignments. Then confirm through CLI.

AZ104_RBAC_VNET_ID=$(az network vnet show \
  --resource-group "$AZ104_RBAC_RG" \
  --name "vnet-az104-rbac-lab" \
  --query id -o tsv)

az role assignment list \
  --scope "$AZ104_RBAC_VNET_ID" \
  --include-inherited \
  --query "[?principalId=='$AZ104_RBAC_GROUP_ID'].{role:roleDefinitionName, assignedAt:scope, principal:principalName}" \
  -o table

Evidence: The output should show Reader assigned at the resource-group ID while you are evaluating the VNet. Role propagation can take time; a short delay is not proof of a wrong model.

5

Test the boundary mentally

Answer before looking at the explanation:

  1. Can the group modify the VNet? No—Reader does not grant writes.
  2. Can the group view a sibling resource in the same lab resource group? Yes—same parent scope.
  3. Can it view a different resource group solely because of this assignment? No—the assignment does not travel sideways.
  4. Can it create users in Entra ID? No—Azure Reader is not a directory role.
6

Remove access, then clean up

az role assignment delete \
  --assignee-object-id "$AZ104_RBAC_GROUP_ID" \
  --role Reader \
  --scope "$AZ104_RBAC_RG_ID"

az group delete --name "$AZ104_RBAC_RG" --yes

Verify: Confirm the role assignment is absent and the lab resource group is gone. Delete the lab group only if you created it solely for these lessons.

Evidence gate

Show or explain: the three parts of the assignment, why the scope was the resource group, where inheritance appeared, why Reader did not authorize writes, and what permission was required to create the assignment.
