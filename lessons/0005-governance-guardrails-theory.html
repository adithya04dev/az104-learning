Azure governance · Tool selection

Use each guardrail for the job it actually does.

Northstar’s Pulse product is moving from one sandbox to ten subscriptions. You must preserve developer speed while controlling access, configuration, accidental deletion, classification, and spend.

The six-question matrix

QuestionPrimary toolWhat it does not do
Who may perform an Azure action?Azure RBACDoes not require every deployed resource to meet a configuration rule.
What configuration is permitted or compliant?Azure PolicyDoes not replace identity authorization.
Must this resource resist control-plane deletion or change?Resource lockDoes not protect data-plane content and is not a permission grant.
How is this resource classified for ownership, environment, or cost?TagsDo not authorize, enforce by themselves, or inherit automatically.
Where should access and policy inherit across subscriptions?Management groupsDo not contain deployable resources directly.
Who should be notified as spend approaches a threshold?Cost Management budgetDoes not stop resources or cap consumption by itself.

Policy: definition → assignment → evaluation → response

Definition→Initiative (optional)→Assignment + parameters→Evaluation→Effect / compliance

A policy definition describes a business rule in JSON and specifies an effect. An initiative groups definitions around a larger outcome. Assignment binds the definition or initiative to a scope; parameters make it reusable. Exclusions can remove subscopes from an assignment.

Audit

Report non-compliance without blocking the request. Useful before enforcement.

Deny

Block a non-compliant create or update request. It does not retroactively delete existing resources.

Modify / DeployIfNotExists

Alter or deploy related configuration, often requiring a managed identity and remediation for existing resources.

Existing non-compliant resources are not magically corrected just because a modify or deploy-if-not-exists assignment exists. Remediation is a distinct operational step.

Locks: blunt protection with sharp edges

CanNotDelete permits authorized modifications but blocks deletion. ReadOnly blocks control-plane updates and deletion. Parent locks inherit, and the most restrictive inherited lock takes precedence.

Locks apply to control-plane operations, not data-plane operations. A ReadOnly lock can also block operations that look “read-like” in the portal but use POST or require writes—for example, starting a VM. Always test service consequences.

Pulse production incident

An Owner cannot delete a locked resource group

This is expected: the lock applies regardless of the user’s otherwise sufficient RBAC permission. The user also needs authority to remove the lock before deletion can succeed.

Tags classify; Policy can make classification reliable

Tags are plain-text key/value metadata on subscriptions, resource groups, and many resources—but not management groups. Resource tags do not automatically inherit a parent resource group’s tags. If Pulse requires every resource to have CostCenter=Pulse, use a tag strategy plus Policy rather than assuming inheritance.

Never place secrets or sensitive personal data in tags. Tag values are visible through many management and reporting surfaces.

Management groups scale the scope

Management groups sit above subscriptions. Azure RBAC and Policy assignments can inherit through nested management groups into subscriptions and resources. Every directory has one root management group, so assignments there can reach the entire hierarchy.

Enterprise design

EU data-residency rule

Put relevant subscriptions beneath an EU management group and assign an allowed-locations policy there. Do not assign a global rule at the tenant root unless every subscription truly shares it.

Budgets alert; they do not apply the brakes

Budgets compare actual or forecast cost with thresholds and notify configured recipients. Cost data is delayed, evaluation is periodic, and crossing the threshold does not stop workloads. Automated reactions require additional mechanisms and careful design.

Exam trap

“Prevent the team from spending more than ₹X”

A budget alone cannot guarantee that. It informs and can integrate with an action group at supported scopes, but it is not a hard spending cap.

Check your decisions

1. Every new resource must include an Environment tag. Which primary control enforces this?

2. An authorized engineer must be prevented from accidentally deleting a production resource, while updates remain possible.

3. A monthly budget reaches 100%. What happens automatically?

4. A tag is added to a resource group. What happens to existing child resources by default?
